# Birth inputs — Plan

How plans work: this file fixes **what comes first and when a step is done**. Agents manage the
details themselves: they may add working files in this `plan/` folder (one per track or phase,
e.g. `A2.md`), tick steps and record findings. They never change DESIGN, DECISIONS, FORMATS or
MATH; a design question stops the work and goes to the architect. Rules for every plan:
[docs/README.md](../../README.md#rules-for-every-plan).

## With core Step 1 (Track A2, sub-step 10)
- `soul.yaml` becomes the birth certificate (name, language, persona, principles).
- The cognition numbers now in `soul.yaml` move to a default prior: knobs, calibration and
  constants ([FORMATS.md](../FORMATS.md)).

## Step 7 — Born from a prior (D17, D25)
- Loading a prior at birth with the loading rules; a default prior in the repository.
- Done when: a fresh soul born from the default prior passes the replay suite with empty memory.
