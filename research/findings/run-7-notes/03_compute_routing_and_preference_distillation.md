## 2. Deep Synthesis: `compute_tier` Routing & Distillation/Preference Training on `1M` Gated DeltaNet-2

### Part 1: Adaptive System-1.5 / System-2 Compute Routing (`compute_tier`)

#### 1.1 Why MonoAgens Needs `compute_tier` (System-1.5 $\rightarrow$ System-2 Bridge)
MonoAgens already implements **System-1 / System-1.5** gating via its sub-5 ms Pure-Rust neural controller (`1M + Gated DeltaNet-2` measured at `4.55 ms` in `--release`, [`2026-11-21-v2-offline-test-drive.md#L111`](file:///home/muqsith/Projects/Mono/research/findings/2026-11-21-v2-offline-test-drive.md#L111)) to decide *whether* to wake System-2 (`Silent / Note / Wait / Go`). However, **once `Go` fires**, System-2 currently behaves monolithically:
1. `wake_reasoning_for_event_with_extra` ([`context_emit.rs#L74`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/context_emit.rs#L74)) always pulls `core.config().max_recalled_memories.max(1)` items from memory.
2. `OpenAiModelProvider::invoke` ([`openai.rs#L569-L571`](file:///home/muqsith/Projects/Mono/crates/reason/src/model/openai.rs#L569-L571)) always injects the static provider-wide `self.config.reasoning_effort` (and same `model` / `output_limits`).

Recent 2026 economics papers expose how wasteful this monolithic System-2 contract is:
- **Sun et al. (`arXiv:2610.34491` `[PP]`):** Fixed high reasoning effort spends up to **42×** more on easy turns and introduces "lost instances" (overthinking breaks simple responses).
- **Wani et al. (`arXiv:2608.26235` `[PP]`):** Knowledge-recall / routine social turns have low Task Efficiency Score (`TES`) under heavy reasoning tokens, whereas multi-constraint planning/conflict checks have high `TES`.
- **Moon (`arXiv:2608.16956` `[PP]`):** Explicit high-effort API contracts add significant per-call dollar cost (`+$0.01031/call`) for marginal/insignificant accuracy gain unless selectively routed.

#### 1.2 Minimal Architectural Design in `1M + Gated DeltaNet-2`
Following **Kassenaar et al. (`arXiv:2608.20256` `[PP]`)** and **DAHR (Jul 2026 `[PP]`)**, we add a **3-class linear head** `head_compute_tier: Linear(d_model, 3)` over `h_mean` in [`MonoNeuralController`](file:///home/muqsith/Projects/Mono/training/src/monoagens_train/model.py#L164-L182) and [`forward_step`](file:///home/muqsith/Projects/Mono/crates/core/src/neural/forward.rs#L279-L298):

| Tier Index | `ComputeTier` | Coupled `MemCon` Recall Depth | Coupled `ReasoningEffort` / Gateway Profile | Typical Trigger Regime |
|---|---|---|---|---|
| `0` | **`Fast` (`Low`)** | `Light` (`k = min(4, max_recalled)`, skip expensive proc expansion) | `ReasoningEffort::Low` (or fast/flash model profile if configured) | Simple phatic reply, dyadic greeting, unambiguous single-fact acknowledgment (`x_num[13]` high or not needed, `p_verify` low, low epistemic JSD). |
| `1` | **`Standard` (`Medium`)** | `Standard` (`k = max_recalled / 2` or default `k`, standard salience threshold) | `ReasoningEffort::Medium` | Normal conversational turn with moderate context history or open topic continuity. |
| `2` | **`Deep` (`High`)** | `Deep+Proc` (`k = max_recalled` + active procedures/lessons + promise/conflict chain) | `ReasoningEffort::High` (or frontier/heavy model profile) | `imminent_promise_debt > 0`, `pending_belief_uncertainty > 0`, high `p_verify` / `p_uncertainty`, high `TabM` `epistemic_uncertainty`, or multi-party conflict. |

**Parameter & Latency Overhead on `1M` (`d_model = 224`):**
- New weights: `3 * 224 + 3 = 675` `f32` parameters (`+0.055%` on top of `1,219,689` params).
- Runtime compute: 3 dot products of length `224` (`672` FMAs) + 3-way softmax = **< 0.001 ms** (`< 1 µs`), preserving the sub-5 ms budget.

#### 1.3 Risk-Sensitive Escalation & Coupling with Existing Heads (`p_verify`, `epistemic_uncertainty`, `MemCon`)
Rather than relying on `head_compute_tier` in isolation, **ODAR (`arXiv:2602.23681` `[PP]`)** and **DAHR (Jul 2026 `[PP]`)** show that routing should fuse learned tier logits with **uncertainty and context-dispersion signals** — two signals MonoAgens *already computes* in [`forward.rs#L260-L286`](file:///home/muqsith/Projects/Mono/crates/core/src/neural/forward.rs#L260-L286) (`epistemic_uncertainty` from `TabM` JSD, `p_uncertainty`, and `p_verify`, which Run 6 `C-4` noted are currently unused!):
1. **Confidence / Risk-Sensitive Escalation Rule (Zero Extra Parameters):**
   - Let $p_{\text{tier}} = \text{softmax}(\ell_{\text{tier}} / T_{\text{tier}})$ over `[Fast, Standard, Deep]`.
   - Deterministic safety floor (active-inference style): if `epistemic_uncertainty > tau_epi` OR `p_verify > tau_ver` OR `commitments.fires_or_answers_expectation`, **clamp minimum tier to `Standard` or `Deep`** (e.g., `Fast` cannot fire when `p_verify >= 0.65` or `pending_belief_uncertainty > 0.5`).
2. **Start-Low, Escalate-on-Failure Fallback (`arXiv:2610.34491` `[PP]`):**
   - If a `Fast` (`Low`) wake returns `ProviderFailureClass::InvalidOutput` or fails a deterministic post-check (e.g., `check_citation_lock` in `context_emit.rs`), Core/Gateway can retry once at `Standard` or `Deep` without inflating normal-path token cost.
3. **Purpose-Aware Defaults (`ModelPurpose`):**
   - `ModelPurpose::Classify` (condition/goal/gist verification, [`step.rs#L1557`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/step.rs#L1557), [`L3320`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/step.rs#L3320), [`L3427`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/step.rs#L3427)): structurally bounded verdict schema — should default to `Fast/Low` unless `p_verify` / similarity is borderline near `[lo, hi]`.
   - `ModelPurpose::Consolidate` (sleep consolidation, [`sleep_and_beliefs.rs#L605`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/sleep_and_beliefs.rs#L605)): runs off the critical reply path on idle ticks — stays `Standard` or `Deep` per profile.
   - `ModelPurpose::Reason` ([`context_emit.rs#L668`](file:///home/muqsith/Projects/Mono/crates/core/src/turn/context_emit.rs#L668)): directly routed by `compute_tier`.
4. **Projected Cost & Latency Impact (UNMEASURED locally):**
   - Across verified 2025–2026 benchmarks, difficulty-aware routing reduces inference cost by **38%–46%** (`DAHR`), **49.5%** (`Think When Needed`), **≤60%** (`BEST-Route`), **74.31%** (`LLM Router`), and **82%** (`ODAR`). In MonoAgens chat streams dominated by routine turns, routing ~60–75% of `Reason` wakes to `Fast/Low` + `Light` recall is projected to yield **50–70% API cost & reasoning-latency savings**, **explicitly unmeasured** until benchmarked in `monoagens-lab`.

### Part 2: Teacher Reasoning Distillation & Offline Preference Optimization for Tiny `<1–2M` Controllers

#### 2.1 Diagnosis: Why Current Supervised CE/BCE (`train_multitask.py`) Hits a Ceiling
Inspecting [`train_multitask.py#L321-L377`](file:///home/muqsith/Projects/Mono/training/src/monoagens_train/train_multitask.py#L321-L377) alongside [`2026-11-21-v2-offline-test-drive.md#L160-L179`](file:///home/muqsith/Projects/Mono/research/findings/2026-11-21-v2-offline-test-drive.md#L160-L179) reveals three exact gaps left by Run 5's unimplemented `R-62` Stages 2 & 4:
1. **No Teacher Soft/Reasoning-Trace Signal (Missing Stage 2):** All 10 training corpora feed hard `0/1` or 4-class integer labels. As **Bhagtani et al. (`arXiv:2603.11409` `[PP]`)** prove, zero-shot LLMs fail group turn-taking, whereas **label-conditioned reasoning-trace distillation** yields **+23 pp** balanced accuracy. Similarly, **DP3O (`arXiv:2609.06893` `[PP]`)** and **daDPO (`arXiv:2506.15717` `[PR]`)** show soft preference probabilities carry variance-reducing "dark knowledge" that hard labels discard.
2. **Symmetric Cross-Entropy Ignores Turn-Taking Preference Orderings:** In `dev-07-habituation` (`0/5 PASS` after retrain, false `Go` at `5010 ms` when `e_256 = 0`) and `dev-08-patience` (`seed=1` firing `Go` at `1010 ms`), `Silent > Wait > Go` or `Wait > Silent > Go` is strongly preferred over `Go`, yet hard CE penalizes `Go` and `Silent` identically once misclassified, and cannot encode **relative ordering** (`Silent > Wait > Go`) or **asymmetric false-speak annoyance** ($\lambda_{\text{false\_go}} > \lambda_{\text{missed\_go}}$).
3. **Shortcut Reliance Under Vectorless (`e_256 = 0`) & Temporal Gaps:** Even with 70% vectorless dropout in [`augment.py#L47`](file:///home/muqsith/Projects/Mono/training/src/monoagens_train/augment.py#L47), the controller still interprets a `4.0 s` gap with `e_256 = 0` as a fresh `Go` prompt because standard CE lacks **counterfactual invariance penalties** (`CFPO`, `arXiv:2606.23206`).

#### 2.2 Four-Stage Offline Upgrade (Zero Runtime Parameters, Zero Runtime Latency)

All four refinements operate **strictly offline in `training/src/monoagens_train/`** on the exact same `1M` `MonoNeuralController` weights (`+0` runtime latency, `+0` inference complexity):

##### Stage 2A — Offline Teacher Reasoning-Trace-Informed Dark-Knowledge Distillation
Because `MonoNeuralController` is a **non-autoregressive `<1–2M` classifier** (it cannot emit CoT tokens at runtime without breaking `<5 ms` latency and `ARCHITECTURE.md` invariants), we distill teacher reasoning *into its internal `h_t` and logit geometry offline*:
1. **Offline Teacher Annotation (OSI-Clean Data Only):** On hard/ambiguous samples from OSI-clean datasets (`when2speak`, `ubuntu_irc`, `proactive_bench`, `capa`, `SEADialogues` — **never** `CC-BY-NC-ND-4.0` `Speak or Stay Silent` data), query an offline frontier teacher *with* a structured reasoning prompt (*"Explain in 1–2 sentences why the assistant should `[Silent, Note, Wait, Go]` and whether `Fast/Standard/Deep` reasoning is warranted, then output calibrated probabilities $q_{\text{gate}} \in \Delta^3$, $q_{\text{tier}} \in \Delta^2$."*).
2. **Dark-Knowledge KL + Variance-Reduced Preference Distillation (`DP3O` / `daDPO`):**
   $$\mathcal{L}_{\text{KD}} = \tau_{\text{kd}}^2 \, D_{\text{KL}}\!\left(\text{softmax}(z_{\text{teacher}} / \tau_{\text{kd}}) \;\|\; \bar{p}_{\theta}(\cdot \mid x_t, h_{t-1})\right)$$
   where $\bar{p}_\theta$ is the `TabM` ($k=8$) ensemble-mean distribution. Crucially, the teacher's reasoning trace sharpens *when* `Wait` vs `Silent` vs `Go` is genuinely ambiguous (e.g., `p_wait = 0.55, p_silent = 0.35, p_go = 0.10`), transferring dark knowledge into the `1M` controller without emitting a single token at runtime.
3. **Lagrangian Oracle Supervision for `compute_tier` (`arXiv:2604.14853` `[PP]`):**
   - For each training turn, evaluate teacher/proxy correctness and token cost across `[Fast, Standard, Deep]`; assign oracle tier $c^* = \arg\max_{c \in \{0,1,2\}} [\text{Utility}(c) - \lambda_{\text{budget}} \cdot \text{Cost}(c)]$, and train `head_compute_tier` via cross-entropy + soft KL (sweeping $\lambda_{\text{budget}}$ produces a Pareto family of checkpoints).

##### Stage 4A — Closed-Form Categorical Pairwise DPO & Margin Optimization (for Ordered Turn-Taking & Hard Negatives)
For a 4-class controller (`gate_4`), DPO requires **no generation rollouts and no sequence-length normalization**—the policy ratio is exact in closed form! Let $\pi_\theta(a \mid s_t)$ be the student's calibrated `gate_4` probability and $\pi_{\text{ref}}(a \mid s_t)$ be the frozen Phase 3 SFT checkpoint:
- **Mine Hard Preference Triples $(s_t, a^+ \succ a^-)$:**
  - From Lab failures (`dev-07-habituation` repeated stimulus $\Rightarrow$ `Silent > Wait > Go`; `dev-08-patience` open floor $\Rightarrow$ `Wait > Silent > Go`; missed commitment $\Rightarrow$ `Go > Wait > Silent`) and `SODA`-style static snapshots of Phase 3 mistakes (`arXiv:2604.03873`).
- **Closed-Form Categorical DPO + Margin Loss (weighted by `T-DUR` uncertainty, `arXiv:2606.27814`):**
  $$\mathcal{L}_{\text{DPO}}(s_t, a^+, a^-) = -w_t \log \sigma\!\left(\beta \left[\log\frac{\pi_\theta(a^+ \mid s_t)}{\pi_{\text{ref}}(a^+ \mid s_t)} - \log\frac{\pi_\theta(a^- \mid s_t)}{\pi_{\text{ref}}(a^- \mid s_t)}\right] - \gamma\right)$$
  where $w_t = 1 + \alpha \cdot \text{JSD}_k(s_t)$ (`T-DUR`-inspired disagreement reweighting focuses updates on turns where `TabM` members disagree), and $\gamma > 0$ enforces an explicit logit margin between `Silent`/`Wait` and `Go`.
- **Hierarchical Segment Decoupling (`HiPO`, `arXiv:2604.20140` `[PP]`):** Compute separate DPO/margin losses for `gate_4` and `compute_tier` (`Deep > Standard > Fast` on conflict turns; `Fast > Standard > Deep` on trivial phatic turns) so turn-taking and compute-budget gradients do not cross-contaminate.

##### Stage 4B — Unpaired Prospect-Theoretic KTO (`arXiv:2402.01306`) for Asymmetric False-Speak Aversion
When logged Lab or real chat traces provide **unpaired binary outcomes** (*"did this single `Go` / `Wait` turn help or annoy?"*), **KTO** directly encodes **asymmetric false-speak loss aversion** without needing counterfactual action pairs:
$$\mathcal{L}_{\text{KTO}}(s_t, a_t, y_t \in \{+1, -1\}) = \begin{cases} \lambda_D \left[1 - \sigma\!\left(\beta r_\theta(s_t, a_t) - z_0\right)\right] & y_t = +1 \\ \lambda_U \left[1 - \sigma\!\left(z_0 - \beta r_\theta(s_t, a_t)\right)\right] & y_t = -1 \end{cases}$$
where $r_\theta(s_t, a_t) = \log \frac{\pi_\theta(a_t \mid s_t)}{\pi_{\text{ref}}(a_t \mid s_t)}$ and setting $\lambda_U \approx 2.0\text{–}3.0 \times \lambda_D$ directly penalizes false `Go` interruptions (`dev-07`, `low_value_message_rate`) harder than conservative `Silent`/`Wait` deferrals.

##### Stage 4C — Offline Counterfactual Risk Minimization (CRM) + Counterfactual Feature Invariance (`CFPO`)
1. **Exact Propensity Logging Already Exists in Core!** When `config.stochastic_gate_sampling = true` ([`decide.rs#L216-L256`](file:///home/muqsith/Projects/Mono/crates/core/src/gate/decide.rs#L216-L256)), Core draws `SeededRng::draw_unit` against `neural.gate_probs` and persists the exact propensity vector `neural.gate_probs` inside `DecisionTrace` ([`decide.rs#L109-L120`](file:///home/muqsith/Projects/Mono/crates/core/src/gate/decide.rs#L109-L120)). Thus MonoAgens already logs exact logging propensities $\mu(a_t \mid s_t) = \text{gate\_probs}[a_t]$!
2. **Clipped IPS + Empirical Variance Regularization (Swaminathan & Joachims, ICML 2015 `[PR]` + `CoRM-RAG`, `arXiv:2605.01302` `[PR]`):**
   $$\hat{R}_{\text{CRM}}(\theta) = \frac{1}{N}\sum_{i=1}^N \underbrace{\min\!\left(M, \frac{\pi_\theta(a_i \mid s_i)}{\mu(a_i \mid s_i)}\right) c_i}_{\text{clipped IPS cost}} + \lambda_{\text{var}} \sqrt{\frac{\widehat{\text{Var}}_i(\tilde{w}_i c_i)}{N}} + \lambda_{\text{KL}} D_{\text{KL}}(\pi_\theta \| \pi_{\text{ref}})$$
   where $c_i \in [0, 1]$ is the rollout cost (e.g., $c_i = 1.0$ for a `false_speak` or wasted `Deep` wake, $c_i = 0.0$ for valid `Go` or proper `Wait -> Yielded`), clip $M \in [5, 10]$ prevents IPS blow-up, and the variance + KL regularizers prevent policy collapse on rare `Wait` actions.
3. **Counterfactual Context Invariance (`CFPO`, `arXiv:2606.23206` `[PP]`):** Pair each training sequence $(e_{256}, x_{\text{num}})$ with its vectorless counterfactual $(0_{256}, x_{\text{num}})$ on timing-only/habituation regimes (`dev-07`/`dev-08`) and add $D_{\text{JS}}(\pi_\theta(\cdot \mid e_{256}, x_{\text{num}}) \,\|\, \pi_\theta(\cdot \mid 0_{256}, x_{\text{num}}))$ so the controller cannot cheat by using random vector presence as a `Go` trigger.

##### RTX 4060 8 GB Compute Budget
Because `train_multitask.py` already runs on precomputed `256d + 18d` numpy shards (`< 1 GB` VRAM, Phase 3 took `263.05 s` for 10 epochs in [`2026-11-21-v2-offline-test-drive.md#L150`](file:///home/muqsith/Projects/Mono/research/findings/2026-11-21-v2-offline-test-drive.md#L150)), adding Stage 2 KL + Stage 4 DPO/KTO/CRM + `head_compute_tier` adds negligible memory (`< 50 MB`) and ~30–60s per post-training pass on the RTX 4060.
