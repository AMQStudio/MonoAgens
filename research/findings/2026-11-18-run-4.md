## Executive Summary & Owner Choices Needed

1. **There is no single "published LoCoMo comparison protocol"; two distinct generations exist in the literature (`R-55`):**
   - **Generation 1 (2025 Comparative Paper Standard):** Mem0 (`arXiv:2504.19413v1`, `mem0ai/mem0` @ `aae5989e`), Zep's replication (`getzep/zep-papers` @ `4b7f26cc`), and Letta's blog (`letta-ai/letta-leaderboard` @ `802a7942`) all **exclude LoCoMo Category 5 (adversarial, 446 QAs)** and evaluate **1,540 QAs** (Categories 1–4). Mem0 & Zep use **`gpt-4o-mini`** for both answerer and judge (`ACCURACY_PROMPT`, binary `CORRECT`/`WRONG` JSON); Letta uses **`gpt-4o-mini`** as the agent and **`gpt-4.1`** with `GRADER_TEMPLATE` (`A`/`B`/`C`) as judge.
   - **Generation 2 (2026 `mem0ai/memory-benchmarks` @ `4b61c5d3`):** Uses **`gpt-5`** for answerer & judge, **`top_k = 200`**, a LoCoMo-specific date-range hint (`"All events occurred in 2022-2024"`), and a lenient unified `_JUDGE_TEMPLATE` (14-day tolerance + partial credit). Mem0 Platform scores `91.56%` (`1410/1540`) under this protocol vs `66.88%` / `68.44%` in the 2025 paper.
   - **OpenCode Go availability gap for Phase 0:** Checked live `https://opencode.ai/inference/go/v1/models` (32 models) and `https://opencode.ai/inference/v1/models` (88 models) on `2026-11-18`. **`gpt-4o-mini`, `gpt-4o`, and `gpt-4.1` are NOT served by OpenCode Go or OpenCode Console Pay-as-you-go.** Phase 0 under the published model requires an external key (OpenAI direct / Azure OpenAI), as `design.md` Decision 7 already anticipated.

2. **Metering proxy is mandatory for parity across the four frameworks (`R-56`):**
   - **`mem0ai==2.2.1`** (`OpenAILLM.__init__`) does **not** accept custom HTTP headers (`default_headers` or `http_client`), and ignores `reasoning_effort` for `deepseek-v4.1-flash` unless `is_reasoning_model=True` is set.
   - **`graphiti-core==0.31.2`** must use `OpenAIGenericClient(..., structured_output_mode='json_object')` (Chat Completions, because `OpenAIClient` uses the Responses API which OpenCode Go does not use for DeepSeek), and `OpenAIGenericClient` does **not** emit `reasoning_effort`.
   - **`letta-client==1.12.1`** talks to a separate Letta server (`letta/letta:latest` V1 Docker, **deprecated** in current Letta docs in favor of the Node.js `letta server --backend local` App Server which uses `@letta-ai/letta-agent-sdk`, not `letta-client`), and neither exposes per-conversation `x-opencode-session` header injection to upstream OpenAI calls.
   - **`langmem==0.0.30`** (`ChatOpenAI`) natively supports `base_url`, `default_headers`, and `reasoning_effort`, and runs in-process with `InMemoryStore`.
   - Therefore, **all four adapters must route LLM traffic through the Lab's local metering proxy** to enforce `model`, `reasoning_effort="high"`, `User-Agent`, and `x-opencode-session`.

3. **OpenCode Go caching telemetry bug found in `crates/reason/src/model/openai.rs` (`R-58`):**
   - OpenCode's Inference API (`opencode.ai/docs/console/api/inference.md`) reports cached token reads in **`usage.opencode.tokens.cache_read`** (and writes in `cache_write_5m` / `cache_write_1h`), where `opencode.tokens.input` **excludes** cache reads and writes.
   - [`crates/reason/src/model/openai.rs`](file:///home/muqsith/Projects/Mono/crates/reason/src/model/openai.rs#L157-L160) only parses `usage.prompt_tokens_details.cached_tokens` and omits `cache_read` from `OpenCodeTokenDetails` — directly explaining why `design.md` noted pilot records showed no cached-token values.
   - For `deepseek-v4.1-flash`, OpenCode Go prices uncached input at **`$0.15/1M`**, cached read at **`$0.003/1M`** (**98% / 50× discount**), output at **`$0.60/1M`**, with a **`2×` peak-hour multiplier** Mon–Fri `01:00–04:00` and `06:00–10:00 UTC` (`08:00–11:00` and `13:00–17:00 WIB`), and a **`$100/mo` Go / `$200/mo` Go Plus** monthly allowance (`20%` per 5-hour window, `50%` per weekly window resetting Monday `00:00 UTC`).

### Owner Choices Needed Before Implementation

1. **Phase 0 LoCoMo baseline protocol (`R-55`):**
   - *Option A (2025 Paper Standard — recommended for apples-to-apples historical comparison):* `gpt-4o-mini` answerer & `gpt-4o-mini` judge (`ACCURACY_PROMPT`, `temperature=0`), comparing directly against `arXiv:2504.19413` Table 1/2 (`Mem0 66.88%`, `Mem0^g 68.44%`, `Full-context 72.90%`, `LangMem 58.10%`) and `zep-papers` (`Zep 75.14%`), plus Letta (`74.0%`, noting Letta used `gpt-4.1` judge). Requires an external OpenAI/Azure key.
   - *Option B (2026 `memory-benchmarks` Protocol):* `gpt-5` answerer & judge, `top_k=200`, against `locomo_results.json` (`Mem0 Platform 91.56%`). Note: `ANSWER_GENERATION_PROMPT` injects `"All events occurred in 2022-2024"`, which encodes dataset-specific knowledge; `gpt-5` is available on OpenCode Console Pay-as-you-go (not Go).
   - *Option C (Dual scoring on Category 5):* Run Categories 1–4 under the chosen judge prompt **and** separately score Category 5 (446 adversarial QAs) using official `snap-research/locomo` `evaluation.py` refusal check + F1 on Cat 1–4, keeping Cat 5 apart as [`memory-comparison/spec.md`](file:///home/muqsith/Projects/Mono/openspec/changes/lab-memory-comparison/specs/memory-comparison/spec.md#L77-L85) already specifies.
2. **Phase 0 LongMemEval-S baseline (`R-55`):** Note `proposal.md` restricts Phase 0 to LoCoMo only; when Phase 2 runs LongMemEval-S in head-to-head mode (`deepseek-v4.1-flash` judge per `design.md`), published `gpt-4o` (`Zep 71.2%`) and `gpt-5` (`Mem0 OSS 91.0%`) numbers cannot be compared head-to-head without `_non_official_judge` separation.
3. **Letta server runtime (`R-56`):**
   - *Option A (V1 Docker `letta/letta:latest` + `letta-client==1.12.1`):* Matches `lab/adapters/pyproject.toml` and `letta-leaderboard`, bundles Postgres+pgvector (~1–2.5 GiB RSS), but is marked deprecated in Letta docs and requires verifying whether its `pgvector` schema accepts `embedding_dim=256` without zero-padding to `1536`.
   - *Option B (Letta App Server `@letta-ai/letta-code` + Node 22.19+):* Current supported local server (`letta server --backend local`), but drops `letta-client` Python API in favor of `@letta-ai/letta-agent-sdk` (TypeScript/WebSocket) and requires a Node bridge.
   - *Option C (Gap / Skip if V1 Docker fails parity):* Per `memory-comparison/spec.md`, report Letta as a gap with reason rather than substituting.
4. **Graphiti graph database backend (`R-56`):**
   - *Option A (`graphiti-core[falkordb]` + `falkordb/falkordb:latest` Docker, or `graphiti-core[falkordblite]` embedded on Python 3.12):* ~0.5–1.5 GiB RSS (or zero-Docker in-process with `falkordblite`), requires adding the extra to `pyproject.toml`.
   - *Option B (`neo4j` Docker, base dep already in `pyproject.toml`):* JVM heap typically ~1.5–3 GiB RSS; must run sequentially with other heavy containers on this 14 GiB RAM host (`~5.0 GiB` currently available per `free -h`).
5. **Ingestion granularity for Phase 1/2 (`R-57`):**
   - **Letta:** FileSystem session upload (`0` LLM calls, matching `letta-leaderboard` `74.0%` protocol) vs conversational `agents.messages.create` turn-by-turn (`≥5,882` agent LLM calls on LoCoMo!).
   - **Mem0:** Paper protocol (`batch_size=2` turns × **2 speakers** = 2× ingestion cost) vs `memory-benchmarks` (`CHUNK_SIZE=1` for LoCoMo once per conversation, `CHUNK_SIZE=2` for LongMemEval).
   - **LangMem:** `MemoryStoreManager` per message pair/session (1 LLM call/unit) vs Mem0 paper's per-message `create_react_agent` × 2 speakers (`17.99s` search latency, ~12k+ LLM calls on LoCoMo).
   - **Zep/Graphiti:** Per-message `add_episode` (exact published protocol; costs ~2–6+ LLM calls/turn = ~12k–35k LLM calls across 5,882 LoCoMo turns!).

## R-58 — OpenCode Go Caching & `deepseek-v4.1-flash`

Verified from [`https://opencode.ai/docs/console/go.md`](https://opencode.ai/docs/console/go.md), [`https://opencode.ai/docs/console/api/inference.md`](https://opencode.ai/docs/console/api/inference.md), [`https://opencode.ai/docs/console/harnesses.md`](https://opencode.ai/docs/console/harnesses.md), and live metadata from `https://opencode.ai/inference/go/v1/models` (`2026-11-18`):

1. **Prompt caching & pricing (`deepseek-v4.1-flash` / `deepseek/deepseek-v4.1-flash-1017`):**
   - **Applies:** Yes. Endpoint is OpenAI Chat Completions (`https://opencode.ai/inference/go/openai/v1/chat/completions`), context limit `1,000,000`, max output `384,000`, reasoning efforts `["low", "high", "max"]`, ZDR `true` (renewed monthly, valid through Nov 30, 2026; requires **Global** region enabled in Workspace Settings → Privacy).
   - **List prices (per 1M tokens):**
     - Uncached input (`cost.text.input.price`): **`$0.15 / 1M`**
     - Cached input read (`cost.text.input.cache.read`): **`$0.003 / 1M`** (**2.0% of uncached input price — a 50× / 98% discount**). No separate cache-write fee is defined.
     - Output (`cost.text.output.price`): **`$0.60 / 1M`**
   - **Peak-hour multiplier (`cost.multipliers`):** **`2×` factor** on **Mon–Fri `01:00–04:00 UTC` (`08:00–11:00 WIB`)** and **`06:00–10:00 UTC` (`13:00–17:00 WIB`)**; `1×` outside those windows.
   - **How responses report cached tokens (and bug in `openai.rs`):**
     - `inference.md` specifies responses report `usage.cost`, `usage.opencode.billing_source`, `usage.opencode.list_cost`, `usage.opencode.allowance` (Go only, dollars deducted from monthly allowance), and:
       ```json
       "tokens": { "input": 1200, "output": 300, "reasoning": 120, "cache_read": 8000, "cache_write_5m": 0, "cache_write_1h": 0 }
       ```
       where `opencode.tokens.input` **excludes** cache reads and writes, and `output` includes `reasoning`.
     - **Verified gap in MonoAgens:** [`crates/reason/src/model/openai.rs`](file:///home/muqsith/Projects/Mono/crates/reason/src/model/openai.rs#L157-L160) only reads `usage.prompt_tokens_details.cached_tokens` (`L551`) and omits `cache_read` from `OpenCodeTokenDetails`, which explains why pilot logs showed no cached-token counts despite `$0.003/M` vs `$0.090/M` billing differences noted in `design.md`. Both the metering proxy and `openai.rs` should parse `usage.opencode.tokens.cache_read` (falling back to `prompt_tokens_details.cached_tokens`). *(Note: whether OpenCode's top-level `usage.prompt_tokens` includes or excludes `cache_read` should be logged/checked on the first live proxy call.)*

2. **Role of `x-opencode-session`:**
   - OpenCode Go (`go.md` & `harnesses.md`) requires sending a stable per-conversation session ID in `x-opencode-session` (`ses_...`) so the gateway can **route requests consistently to the same backend worker and reuse its prompt KV cache**, alongside a client-identifying `User-Agent` (e.g., `monoagens-lab/1.0`, not a generic HTTP-library string). Omitting `x-opencode-session` on Go routes risks `HTTP 400 MissingSessionID` or cache-miss routing across workers.

3. **Usage limits & limit-reached behavior:**
   - **Monthly `deepseek-v4.1-flash` allowance (at `opencode.list_cost`, including any `2×` peak-hour factor):**
     - **Go (`$10/mo`):** **`$100/month`**
     - **Go Plus (`$40/mo`):** **`$200/month`**
     - **Go Teams (`$20/member/mo`, 2-seat min):** **`$105/member/month`**
   - **Rolling caps (shared across all paid Go models):**
     - **5-hour window:** **20%** of monthly allowance (`$20` on Go / `$40` on Go Plus), starting on first allowance use.
     - **Weekly window:** **50%** of monthly allowance (`$50` on Go / `$100` on Go Plus), resetting **Monday `00:00 UTC`**.
   - **When a limit is reached:** Paid Go requests are blocked unless **Extra Usage** is turned on in the Console Go page (which falls back to pay-as-you-go Console credits at list price). Free models remain available inside OpenCode, **but free-tier chat models return `HTTP 403` to external API/harness clients** (`inference.md`), so resumable per-conversation checkpointing + rate-limit backoff in the runner is essential.
