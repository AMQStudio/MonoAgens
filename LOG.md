## 2026-11-08 — One Writer for Bind-Mounted Host Files
- `plugins enable` died on a compose deployment with `[Errno 16] Device or resource busy: '/app/config.yaml.tmp' -> '/app/config.yaml'`: `compose.yaml` mounts `config.yaml` as a single file, and `rename(2)` onto a mount point answers `EBUSY`. Four engine writers each rolled their own temp+`os.replace` (`plugins/install.py`, `commands/language.py` for `soul.yaml`, `stores/documents.py` for the mirror documents, `tools/settings.py` for the `settings` tool), so the same failure waited on three more operator paths.
- One writer now: `monoagens/engine/config/write.py::write_text` — temp + `fsync` + `os.replace`, and on `EBUSY` an in-place rewrite of the same inode (mode preserved, temp always removed, a non-`EBUSY` error still raises and leaves the old file). `admin/yaml_io.write_text` keeps its validation and delegates the write, so the CLI and the engine cannot drift again.
- Diagnostics: `plugins install|enable` names `plugin.source` before the digest pin (the real blocker on a fresh deployment), and `plugins ls` prints `plugin.source: (empty)` when fetch is on, so "none configured" no longer hides the next step.
- Proof: `tests/test_config_write.py` — EBUSY fallback keeps the inode and a loadable document, a non-EBUSY write still raises and keeps the old bytes, `plugins enable` succeeds with the rename refused, and the source is named before the pin. Gate: 1521 passed, ruff clean, pyright 0 errors, 10/10 ADRs.

## 2026-11-07 — One Privacy Question, Grounded Claims, and a Warm Default Tone
- Privacy dialogue (`note.md` §10): `PrivacyService.handle_pending` consumes a message only when it really answers — a bare level (`2`, `rahasia`) is read deterministically with no model call, and only an unclear reply reaches one classifier call that now sees the question it answers; anything else is an ordinary turn, so a pending question can no longer swallow the conversation or loop the same line. `review` and `ask_memory` reuse the pending row for the same `memory_ids` (`ApprovalStore.set_payload`) instead of staging a second question; `/approve` and `/deny` route privacy/disclosure rows through the one `decide()` path (deny forgets the memory), so a privacy row never reaches a tool. `privacy.unclear` is retired.
- Wording: the privacy question and its acknowledgements are phrased by the model (`privacy_phrase`, fact code-owned, catalog line as fallback), because a canned sentence lands stiff mid-conversation; memory text still never leaves the host.
- Claim guard (`§10`): `ToolContext.refused` records every `error:`/`denied:`/`pending approval` result, and only such a refusal (or a catalog policy notice) stops the re-ask — a *successful* tool no longer excuses a claim. The judge receives the sender's request and each tool's outcome, so "I cannot attend the meeting" is not a claim while "I cannot read that archive" still is.
- Verified facts (`§10 §2`): the sender's linked addresses (`IdentityStore.links`) join the id set, so a transport handle and a phone number resolve to the same rooms; an empty list now reads "none recorded in this archive".
- Tone: an empty decision falls back to `neutral` (never `curt`), `ensure_reply` keeps a cold tone but never invents one, and `curt`/`angry` styles state that mood colors wording only — never facts, permissions, help, or a refusal.
- Defaults: `voice.affect.enabled` is `false` (experimental mood layer), style and humanize stay on, `voice.sampling.daily_temperature` is 0.7; root `soul.yaml`, `config.yaml`, and the README sample regenerated.
- Commands: `command_name` strips invisible characters and punctuation before the registry lookup, and an unknown command suggests the closest name (`agent.command_hint`).
- Budget and proof: `engine.llm.classifier_max_tokens` (default 64, measured p50 2 / p95 4 / max 4 completion tokens on `deepseek-ai/DeepSeek-V4.1-Flash-1017` with the new `scripts/token_probe.py`) replaces the hardcoded classifier token literals; `scripts/live_e2e.py` drives 12 real-model scenarios (archive, cross-body, group silence/mention, four privacy flows, claim rejection, tone, correction, 30-turn conversation) and passed 12/12.
- Verification: `pytest -q` 1515 passed, `ruff check` clean, `selfcheck` ok, `types.py --check` 0 errors, `adr.py --check` 10/10, `uv lock --check` ok.

## 2026-11-07 — Cross-Surface Continuity, Archive Updates, and Human-Readable YAML
- Continuity (`note.md` §6): the prompt's cross-thread rule now guards *people*, not the sender's own history — a linked person asking about their own DM on another surface gets an answer. `HistoryStore.private_rooms_of` proves the room is theirs (`kind='dm'` + their own message), `thread_history` stops tagging such a read `never leak it` and keeps it out of the `cross_reads` list the guard scans; another person's DM and every group stay fail-closed.
- Linked surfaces (`§6`): `PromptContext.surfaces` renders `IdentityStore.links(person_id)` through `prompts.linked_surfaces` — gateway + address in a DM, gateway names only in a shared room — so the soul knows its accounts and can call `thread_history(gateway=…, chat=…)` without guessing.
- Telegram (`§6`): `ingress.normalize_start` maps the mandatory `/start` (with deep-link payload or `@mention`) to `/help` instead of "unknown command".
- `monoagens update` (`§7`): `admin.service.fetch_archive`/`apply_archive` refresh the code from `main.tar.gz` via `urllib.request` + `tarfile` (no `git`), skipping `config.yaml`, `roles.yaml`, `soul.yaml`, `.env`, `.monoagens`, `.venv`, and `plugins`; `_update_core` then runs `uv sync --locked --no-dev` and keeps the local tree when the download fails.
- Compose lifecycle (`§7`): lifecycle verbs (`update`/`upgrade`, `start`, `stop`, `restart`, `status`, `logs`, `uninstall`) run on the host in the launcher; `compose_update` writes `EXTRAS`, builds the image, runs `db upgrade` in the stack, then `up -d --force-recreate monoagens` (a failed build stops the sequence).
- YAML comments (`§8`): `ROLE_GATEWAY_COMMENTS` spells out `dm`/`groups`/`channels`/`threads`/`topics`/`reply_to_bot`, `GATEWAY_OPTION_COMMENTS` lists choices plus each body's own default (no more "that gateway's own settings dataclass"), the config fallback never says "operator setting", and `SOUL_COMMENTS` explains affect/style/character/humanize with the validators' real values (`volatility`, `profanity`, `safety`). Root `config.yaml` and `soul.yaml` regenerated; `roles.yaml` verified byte-identical.
